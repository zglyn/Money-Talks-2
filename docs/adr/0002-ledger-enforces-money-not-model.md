# Ledger and tools enforce money, not the model

The reallocation agent sequences and explains; it must not be trusted to create purchasing power. Reservations, Available Balance, Program Rules, idempotency, and apply run in tools and the Issuer Ledger (Postgres functions), so a misbehaving or injected model cannot double-spend or bypass caps.

We rejected “smart prompt only” control because v1 shows that path fails under concurrency and over-cap moves. Agent Versions (v1 vs v2) exist to prove that failure and fix for PRISM, not as two products.
